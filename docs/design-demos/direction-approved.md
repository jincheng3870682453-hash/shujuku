## 三、选定结论与后续

- **选定方向**：B · Airtable Grid View 标杆迁移
- **未采纳**：A（日式留白画廊）、C（Rams 工业理性）——骨架与密度策略不采纳，
  但若后续需强化留白节奏（A）或垂直空间压缩（C），可作为局部借鉴。
- **进入 Fallback Phase 6 → 主干流程 Step 2**：把 B 版做扎实，落地到 React 18 + Ant Design 5 生产代码。

### 落地必须继承的 B 版设计语言（5 条方法论迁移）
1. **白色网格画布 + 竖列线**：让「列」成为可见的结构对象，而不是隐形的分割
2. **单元格即编辑点**：hover 描边 + 铅笔角标 + Enter/Esc 语义，编辑说明常驻不藏 tooltip
3. **破坏性操作沉入「更多」菜单**：只用红色文字 + 二次确认注记，与导入导出完全分离
4. **登记条（view bar）合流**：标题 + 统计 + 工具同处一带，不再各自独立成行
5. **彩色 pill 只服务「状态」这一个扫读维度**，其余全部灰阶化

### 落地必须解决的 5 个病灶（spec 6.3）
1. 表格可读性 —— 1px 实色行线 + 实色斑马纹 + 竖列线 + 冻结首列 + tabular-nums
2. 内联编辑可发现性 —— 三态齐备（hover 描边 / 编辑态 2px 框 / 常驻说明文字）
3. 危险操作分级 —— 清空数据·重置沉入更多菜单，红色文字 + 二次确认
4. 垂直空间压缩 —— 统计条+工具栏合成 44px 登记条；拖拽区压成 34px 细条；只读提示 28px
5. **一套 CSS 变量贯穿** —— L1 原始色 → L2 语义层 → L3 度量层，组件只引用 L2/L3，
   彻底消除现有的「tokens / textures / AntD token / 行内硬编码」四套并行体系
