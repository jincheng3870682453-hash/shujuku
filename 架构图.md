## 2. 请求处理流程

```mermaid
sequenceDiagram
    participant U as 用户
    participant FE as React 前端
    participant GW as Flask 网关
    participant Auth as 认证模块
    participant Perm as 权限检查
    participant Audit as 审核引擎
    participant BL as 业务逻辑
    participant DB as 数据库适配器
    participant DS as SQLite / MySQL

    U->>FE: 操作（新增/编辑/删除数据）
    FE->>GW: HTTP Request + Bearer Token
    GW->>Auth: before_request 恢复 Session
    Auth->>Perm: 检查用户权限
    alt 权限不足
        Perm-->>FE: 403 Forbidden
    else 权限通过
        Perm->>Audit: 检查是否需要审核
        alt 非boss + 审核开启
            Audit->>DB: 写入 pending_changes 表
            Audit-->>FE: 200 "已提交审核"
        else boss 或审核关闭
            Audit->>BL: 直接执行业务逻辑
            BL->>DB: SQL 操作
            DB->>DS: 执行
            DS-->>DB: 结果
            DB-->>BL: 结果
            BL-->>FE: 200 操作成功
        end
    end
```

## 5. 审核工作流

```mermaid
stateDiagram-v2
    [*] --> 用户操作: 新增/编辑/删除/字段变更
    
    用户操作 --> 权限检查
    权限检查 --> boss直接执行: boss 角色
    权限检查 --> 审核判断: 非 boss 角色
    
    审核判断 --> boss直接执行: global_audit = false
    审核判断 --> 写入待审核: global_audit = true
    
    写入待审核 --> 待审核队列: pending_changes 表
    
    待审核队列 --> 审核通过: 管理员 approve
    待审核队列 --> 审核驳回: 管理员 reject
    
    审核通过 --> 自动执行: 解析原始操作并执行
    审核驳回 --> 操作取消: 记录驳回原因
    
    自动执行 --> 记录日志: audit_logs 表
    boss直接执行 --> 记录日志
    操作取消 --> 记录日志
    
    记录日志 --> [*]
```
