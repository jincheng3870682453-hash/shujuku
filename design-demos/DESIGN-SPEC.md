# 动态数据登记系统 · UI 全套重构 设计 Spec

> 这是三套设计逻辑的**唯一共同输入**。三版只看这份 spec，互不参考。spec 越具体，三版越不跑偏。

---

## 1. 项目是什么

「动态数据登记系统 Dynamic Registry」v6.0 —— 一个**字段可动态定义的企业级数据登记与管理平台**。
核心能力：用户自由增删字段（7 种类型：文本/数字/日期/下拉/布尔/长文本/文件），录入数据行，
按角色（Boss/HR/Employee/自定义，21 项细粒度权限）分级访问，非 Boss 的写操作进入三级审核流，
附带 ECharts 统计看板、多模型 AI 分析、Excel 导入导出、数据库备份恢复、9 种背景质感主题。

技术栈（重构落地目标）：React 18 + TypeScript + Vite + **Ant Design 5** + TailwindCSS +
Zustand + TanStack Query + ECharts；后端 Flask + SQLite/MySQL；另有 Electron 桌面壳。

**一句话本质**：它不是展示型网站，是**每天要被 HR/管理员盯着填、盯着审、盯着改的工具**。
设计的服务对象是"长时间高频使用的操作员"，不是"第一次点进来的访客"。

## 2. 目标受众与使用场景

| 维度 | 内容 |
|---|---|
| 主要用户 | 企业 HR、部门数据管理员、系统 Boss（管理员） |
| 次要用户 | 只读的普通员工 |
| 使用设备 | **桌面为主**（Electron 桌面端 + 浏览器，1440×900 是典型视口，最小支持 1280×800） |
| 单次时长 | 长会话——连续录入几十上百条、翻页核对、批量审核 |
| 光线环境 | 办公室日常光，非暗房；但产品已有暗色基因（现有全部质感除 paper 外均为暗色） |
| 核心任务 | ① 快速录入/修改数据 ② 定位并核对某条记录 ③ 审核他人提交的变更 ④ 看懂数据分布 |

**推论**：这是**工具型界面**，不是营销页。评判标准是"用三小时眼睛累不累、找一条记录要几秒"，
不是"第一眼炫不炫"。密度要够，可读性要硬，装饰要让位。

## 4. 情感基调与气质关键词

**基调**：可信、精密、克制、有秩序感。是企业工具，不是消费级 App。

**气质关键词（三向可选，但必须落在工具语境内）**：
精密仪器 / 档案柜 / 静默权威 / 温润克制 / 工业理性 / 纸面秩序

**明确不要**：赛博霓虹发光、扫描线、紫渐变背景、玻璃拟态滥用、emoji、圆角过大（>16px）、
装饰性插画、空状态插画堆砌。

## 5. 输出格式与尺寸（三版必须统一，否则无法横向对比）

- **单文件 HTML**（`file://` 双击可开），纯 HTML + CSS，可选 inline React/Babel
- **视口 1440×900**，内容按此宽度设计；允许页面内部滚动
- 四屏通过顶部 tab 切换，tab 样式由各方向自定
- 截图命令：`npx playwright screenshot file:///绝对路径.html out.png --viewport-size=1440,900`
  （若 playwright 不可用，截图失败不算致命，但 HTML 必须产出）
- 字体：优先系统字体栈（`-apple-system / Segoe UI / PingFang SC / Microsoft YaHei`）；
  如需 Google Fonts 用 `<link>` 引入开源字体（Inter / Newsreader / IBM Plex Sans / Source Serif 等均可）

## 6. 已知约束（硬约束，违反即不合格）

### 6.1 技术落地约束（**最重要**）
最终方案要**落地回 React + Ant Design 5**。所以：
- 设计必须能用 AntD 5 的组件语义表达（Table / Form / Menu / Card / Tag / Pagination / Modal / Badge / Drawer）
- 可以用 CSS 变量 + AntD `ConfigProvider` theme token 实现，但**不要设计出 AntD 无法承载的
  自定义结构**（如完全自绘的表格、非标准表单控件）
- 表格必须是真表格（表头 + 行 + 单元格），不能改成卡片流

### 6.2 必含元素
产品名、四屏内容、侧边导航九项、待审核 Badge、分页器、状态 Tag、内联编辑的视觉表达

### 6.3 必须解决的现有病灶（这是重构的核心价值，三版都要正面回应）
1. **可读性**：现有行分隔线 `0.5px rgba(35,37,42,0.6)`、斑马纹透明度 0.015（等于没有）、
   表头 12px uppercase —— 长表格串行。新方案必须让 6 行数据一眼扫完不串行。
2. **编辑可发现性**：现有"双击编辑"只有 tooltip 提示，无 hover 反馈。新方案必须给出明确 affordance。
3. **危险操作权重**：「清空数据/重置」与「导入/导出/刷新」同排同权重。新方案必须分级。
4. **信息密度**：顶部统计条 + 工具栏 + 拖拽区 + 表格，垂直占用过大。新方案要压缩。
5. **体系统一**：现有 4 套样式体系（tokens/textures/AntD token/行内硬编码）互相打架。
   新方案必须做到**一套 CSS 变量贯穿**，并在 HTML 顶部注释里写明你的变量体系。

### 6.4 反 AI slop 底线（任何风格温度都不豁免）
- ❌ 紫渐变、彩色发光、emoji 图标、每个标题配装饰 icon、Lorem ipsum、编造的 stats 装饰
- ❌ 三版共用同一布局骨架只换色换字体（盲测会被一眼识破"换皮"）
- ✅ **三版布局骨架必须至少一项结构性不同**（导航形态 / 内容区构图 / 表格与工具栏的关系）
- ✅ 用真实中文内容（见屏 B 数据）
- ✅ 留白是构图，不是内容缺席

### 6.5 可读性硬底线
正文 ≥14px，标签/注释 ≥12px，正文对比度 ≥4.5:1。留白必须有明确视觉锚点。

## 8. 视觉母题假设（form 推导第五问）

产品本质 = **"结构由用户定义的数据容器"**——字段是活的、列会长出来、行会流动。

候选母题（三版各自从中选或自行推导，**必须写清 form 来自内容的哪里**）：
- **网格/栅格**：表格本身就是母题，把"列"做成可见的结构性元素（列分隔、列标识）
- **登记册/档案**：纸质台账的当代转译——行是有厚度的记录，不是平等的色块
- **活体列**：字段可被增删，UI 里体现"列是对象"（列头可操作、列有自己的状态）
- **刻度/标尺**：数据是量出来的，用刻度感替代装饰感
